# nuclear.academy

A nuclear security learning site: modules, a glossary and source library, and interactive tools that
run in the browser. Author and editor: Howard L. Hall (University of Tennessee, Knoxville).

**Live:** https://nuclear.academy (production, branch `main`) · **Dev:** https://dev.nuclear.academy
(branch `dev`, access-controlled).

## For contributors (including the undergraduate researcher)

Read these before your first commit:

1. This file.
2. The development roadmap and primer (kept in the editor's planning folder; ask for the current
   copy). The short version of the rules is below.

### The rules that matter

- **Work on `dev` (or a branch off it). Never push to `main`.** `main` is protected; only the editor
  merges to it, and every merge is a publication.
- **Open-literature level only.** Everything here is built from published sources — textbooks, the
  IAEA Nuclear Security Series, public NRC/DOE documents, peer-reviewed literature. Nothing that
  describes a real facility's protection, and nothing drawn from non-public material, ever.
- **Every datum has a source.** Data files carry `source`, `source_url`, and `retrieved` for every
  row. Data files under `src/data/` are generated by scripts in `pipelines/` — do not hand-edit
  them; put corrections in the overrides file with a reason.
- **Every page is in the inventory.** `CONTENT_INVENTORY.md` lists each page, its status
  (draft / reviewed / screened / live), its sources, and its owner.
- **Cite with DOIs or permanent links.** Numbered citations in the text; entries in
  `src/content/sources/`.
- **Accessibility is not optional.** Headings in order, alt text on every figure, tools operable by
  keyboard. The build runs checks; do not merge with failures.

### Working locally

```
npm install        # once
npm run dev        # local preview at http://localhost:4321
npm run build      # production build into dist/
npm test           # validation cases (calculators) and link checks
```

Node 20 or later. Cloudflare Pages builds `main` and `dev` automatically on push.

### Layout

```
src/content/modules/   one folder per module (index.md + sections)
src/content/glossary/  one file per term
src/content/sources/   one file per cited source
src/components/tools/  interactive tools (Bateman calculator, facilities map, ...)
src/data/              generated data — never hand-edited
pipelines/             scripts that build src/data from public sources, with provenance
tests/                 validation cases, link and accessibility checks
```
